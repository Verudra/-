## 项目背景
用于跨年活动的现场互动项目：大屏展示一张中国地图（按省份划分）。现场同学扫描大屏上的二维码，在手机端输入昵称并选择省份后，地图上对应省份被“点亮”，形成集体互动效果。

---

## 目标与范围（MVP）

### 核心目标
- 让现场观众通过扫码完成一次简单互动（填写昵称 + 选择省份）。
- 大屏地图能实时反映互动结果（点亮对应省份）。
- 活动现场可稳定运行，支持多人同时提交。

### 不在 MVP 内（明确排除，避免范围膨胀）
- 复杂账号体系、社交关系、排行榜、礼物/积分体系。
- 多主题皮肤、复杂动效、音视频联动。
- 多语言、多活动场次的完整运营后台（除非后续明确需要）。

---

## 参与角色
- 观众（手机端）：扫码、填写昵称、选择省份、提交。
- 主持/工作人员（大屏端）：打开大屏页面、开始/重置活动、展示二维码。
- 系统（服务端）：接收提交、校验、存储、广播省份点亮状态。

---

## 典型用户流程

### 观众（手机端）
1. 扫描大屏二维码进入页面。
2. 输入昵称（必填）。
3. 选择省份（必选，列表或地图点选）。
4. 点击提交。
5. 提示提交成功，并展示“你点亮了：xx省”。（可选：展示当前已点亮数量）

### 大屏（展示端）
1. 打开大屏展示页（全屏）。
2. 页面展示中国地图 + 二维码 + 已点亮统计（可选）。
3. 当有人提交成功后，对应省份立刻点亮。
4. 活动开始前/中途需要时可“重置”（清空点亮状态）。

## 功能需求拆解

### A. 大屏端（展示页）
1. 中国地图展示
	- 省份边界清晰，可独立高亮（点亮）/置灰（未点亮）。
	- 至少支持 31 个省级行政区（含直辖市/自治区；是否包含港澳台需提前确认）。
2. 点亮逻辑
	- 接收到“省份点亮事件”后，将对应省份状态置为已点亮。
	- 重复点亮同一省份时：保持点亮（不闪烁或可轻微提示，后续确认）。
3. 二维码展示
	- 固定展示一个可扫码访问的手机端入口 URL。
4. 活动控制（MVP 建议至少有“重置”）
	- 通过一个隐藏入口或简单按钮触发重置（建议加简单口令，避免误触）。

### B. 手机端（H5 提交页）
1. 表单
	- 昵称：必填，长度限制（建议 1~12 个字符），过滤纯空格。
	- 省份：必选，来源为固定省份列表。
2. 提交
	- 提交成功：提示成功。
	- 提交失败：明确错误原因（例如“省份无效/系统繁忙/网络异常”）。
3. 防重复/体验
	- 提交按钮在请求中禁用，防止连点重复提交。

### C. 服务端（API + 实时推送）
1. 接收提交（创建一次点亮记录）
2. 校验参数合法性（昵称、provinceId）。
3. 保存数据（用于活动复盘/统计）。
4. 广播“省份点亮事件”给大屏端（建议 WebSocket/SSE）。
5. 提供当前点亮状态的查询接口（大屏刷新后可恢复状态）。
6. 支持重置点亮状态（仅工作人员可用）。

## 业务规则（需要你确认/补齐的决策点）

1. 同一观众是否允许多次提交？
	- 方案 A（简单）：允许多次提交，但同一省份重复只记一次点亮。
	- 方案 B（更严格）：限制同一设备/同一 IP 在一定时间内只能提交一次。
2. 统计口径
	- “已点亮省份数”按省份去重。
	- “参与人数”按提交次数 or 去重（需要确认去重规则）。
3. 省份范围
	- 是否包含港澳台？地图是否需要显示？（强烈建议提前确定，避免临时改图）

## 数据模型（建议）

### Province（静态表/配置）
- id: string（如 `CN-11`）
- name: string（如 `北京市`）

### Submission（提交记录）
- id: string
- nickname: string
- provinceId: string
- createdAt: datetime
- clientIp: string（可选，用于限流/排障）
- userAgent: string（可选）

### ProvinceState（当前点亮状态，可由 Submission 聚合得到）
- provinceId: string
- isLit: boolean
- firstLitAt: datetime（可选）
- firstLitByNickname: string（可选）

---

## 接口草案（示例）

### 提交点亮
- `POST /api/submissions`
- 请求：`{ nickname: string, provinceId: string }`
- 响应：`{ ok: true, lit: true }`

### 获取点亮状态（大屏刷新恢复）
- `GET /api/provinces/state`
- 响应：`{ provinces: Array<{ provinceId: string, isLit: boolean }> }`

### 重置（工作人员）
- `POST /api/admin/reset`（建议加简单口令或一次性 token）

### 实时事件（建议其一）
- WebSocket：`event: province_lit { provinceId, nickname, at }`
- 或 SSE：服务端推送事件流

## 非功能需求（现场活动必须考虑）

1. 并发与性能
	- 目标：同时 50~200 人在 10 秒内提交不崩溃（具体人数可再确认）。
2. 实时性
	- 大屏端从提交到点亮的延迟：目标 < 1 秒（同一局域网更稳）。
3. 可靠性
	- 大屏刷新/断线重连后，能从 `GET /api/provinces/state` 恢复。
4. 安全与防刷
	- 至少做基本限流（按 IP/时间窗），避免恶意脚本刷爆。
	- 管理操作（重置）需要保护（口令/环境变量）。
5. 网络与部署
	- 优先建议：活动现场同一局域网部署（更低延迟更稳定）。

---

## 验收标准（MVP）

- 手机端可通过二维码打开，能成功提交昵称与省份。
- 大屏端能实时点亮对应省份，重复提交不会导致错误。
- 大屏刷新后仍能恢复已点亮状态。
- 工作人员能在大屏端触发一次“重置”，地图恢复未点亮状态。
- 在 50 人同时提交的情况下系统可用（无明显卡顿/崩溃）。
